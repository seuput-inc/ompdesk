# Removing the packaged Node main (phase F)

Plan of 24 Nov 2026 for the last step of `.omp/rules/native-rust.md` › Order 4: the packaged Tauri app starts, serves and quits with no Node process on macOS and Windows. Counts are from `docs/rust-inventory/*.tsv` at d9c634351; the slices change as rows land.

**Recommendation:** put the channel router at Tauri’s existing `omp_ipc` boundary. Move one **state owner and its callers** at a time, not one TypeScript file at a time. Remove `node::spawn` last. Removing it earlier would disable not just unported IPC, but also startup, second-instance delivery and quit handling.

## 1. Scope and slices

The eight inventory files contain **372 `port` or `mixed` rows**: `root` 144, `services` 84, `host-imports` 65, `remote` 23, `web` 19, `helpers` 17, `shell` 13, `preview` 7. They are **not 372 `src/**` files or 372 Node implementations**: some rows describe stock Bun code or page-shared logic. `scripts/rust-runtime-scope.ts:74–110` selects rows by status, not Node reachability. Conversely, a `native-client` row is excluded from 372 but still needs a non-Node caller before exit. See `docs/rust-remaining-units.md:22–28`.

The reason letters below quote the actual §1.3 rule, `docs/rust-remaining-units.md:77–81`: **a** “every caller that stays TypeScript already awaits what it calls”; **b** “it does I/O of its own”; **c** “no staying code reads its in-memory state in the same tick”; **d** “moving it duplicates no logic of stock omp, of the page or of `src/shared`.” These are tests for whether a unit can move **alone**, not reasons to retain the desktop Node process.

## 2. The cutover seam

1. **Desktop ingress today.** `src/shared/omp-api.ts:186–198` defines the transport and constructs the page API. `src/preload/tauri.ts:57,128–155,323` calls Tauri `omp_ipc`, unwraps invoke results, serializes sends and installs `createOmpApi(transport)`. Preserve that page API and browser preload.
2. **Rust already has a working interception point.** `native/ompdesk/crates/tauri-shell/src/main.rs:1459–1498` checks the actual WebView URL, registered page identity, document generation and profile-migration gate. At `:1589–1652`, it validates channel/args, handles native feedback reads, otherwise sends `ipc.send` or waits for `ipc.invoke` over the host connection, then rechecks the document. Windows media translation sits on this path. The Tauri command is installed at `:1883`.
3. **Node registration and other callers.** `src/main/shell-host/electron/ipc-main.ts:73–93` receives invoke/send and the separate Preview `sendSync`. `src/main/web/ipc-registry.ts:186–211` exposes registrations both to the Electron-shaped caller and to non-Electron callers; `src/main/web/ws-router.ts:547` calls the registry directly. Some channels already go **Node → Rust**: `src/main/index.ts:924`, `src/main/web/ipc-registry.ts:104–120,147–181`. That path hands policy to a restarted core and queues waiting calls in order. A desktop-only routing change would leave paired clients behind.
4. **Proposed dispatch.** After ingress checks, select by **`(direction, channel)`** from one native ownership table. Registered → native handler; explicitly unmigrated → existing Node handler. Unknown, wrong-direction, denied or failed native calls **never** fall back to Node. In particular, do not retry a mutation on Node after an ambiguous native result. Keep the same envelope, binary handling, deadlines, caller identity and document-generation recheck. Start with the existing feedback reads as the parity case.
5. **Paired calls and events.** For a migrated channel, the still-running Node web adapter must delegate to that same native handler, retaining the authenticated connection identity. Once F lands, the Rust edge dispatches directly. Preserve the distinctions in `src/main/web/ipc-policy.ts:103–119`: pass, web-specific implementation, pairing-admin boundary, transformed/client-only push. Reuse the existing targeted delivery path (`main.rs:1309–1327`, `src/preload/tauri.ts:128–131`); never broadcast a private response as a shortcut. Preview’s cancellable dialog reply is a separate contract, not an ordinary fire-and-forget send.
6. **Each landing.** Move production callers, state, registrations and event producers together; remove that Node implementation in the same change. Reuse the existing parity cases for desktop, paired and core-restart paths. Add a registry check rejecting duplicate ownership and identifying every unserved channel. For ordering-sensitive work, make the **outer** call async but keep check + reservation + effect admission on one owner before yielding. A fresh RPC between those steps does not preserve same-tick semantics.

### Landed: the router (H foundation, first step)

- **Table.** `native/ompdesk/crates/tauri-shell/src/ipc_router.json` lists the channels the shell serves, by direction; `ipc_router.rs` maps each to its handler. Main hands over the rest of `IPC_POLICY` with `ipc.routes` before its first window (`IpcRegistry.routeShell`, `src/main/index.ts`). `omp_ipc` then has three outcomes: native, main, or refused (unknown, wrong direction, before the hand-over). A native call is answered by the shell whatever its handler returns, so no call is ever tried on both owners.
- **Main's callers.** Main learns the native channels from `hello`'s `nativeIpc` and registers them only in its web table, never on `ipcMain`. A paired page (after `ws-router.ts`' permission and quota checks) and an agent's `ompdesk_app` reach the same handler through `ipc.call` with the caller's lane key (`w<wcId>`, `c<connId>`). `handle`/`on` refuse a native channel, and `routeShell` refuses one main already serves.
- **Native today:** `runtime:log-path`, `runtime:log-tail` (the parity case; their Node relay was deleted) and `updater:version` (deleted from `updater.ts`). Then the page's file dialogs, `system:save-dialog`, `system:open-dialog` and `system:save-image` (`page_dialogs.rs`, over the page's window through the dialog presenter main's `dialog.*` requests use), and `session:consume-pending` (a constant `null` on the desktop).
- **Blocked: `system:open-external`.** It needs no Node state, but e2e specs capture opened URLs by replacing Node's `shell.openExternal` (`desktop-tabs`, `first-run-walk`, `github-*`, `mobile-web`, `oauth-login`, `panels-flows`, `real-core`, `remote-devices`, `sign-in-relay`); every URL that came through the page channel would then reach a real browser on the runner. It moves together with a shell-level capture those specs read, so no test opens a real browser.
- **Meter.** `src/main/web/ipc-policy.test.ts` gives every `invoke`/`send` channel exactly one owner and prints how many main still serves.
- **Moving a channel:** add its handler and its line in `ipc_router.json`, delete main's registration, keep `IPC_POLICY`'s entry (the web permission is still checked there until F). A `send` moves only with its order against main's sends settled, since the page's sends reach main in order and a native one overtakes them. A channel whose web answer `ws-router.ts` reshapes (`#shape`) keeps that shaping in main until F.

## 3. Landing order and exit gate

- **H foundation first:** native routing, identity, ordered events and lifecycle hooks. Node still boots the application. **A is a boundary ledger**, discharged as its consuming slices land; it is not an 82-file prerequisite rewrite.
- **B before dependent C/E/F/G writes.** Establish the single preference and startup-state owner early. Then land **C**, including the native tab/spawn capability and close transaction. If a paired or control caller participates synchronously, cut that caller over in the same landing, not in a later mirror cleanup.
- **D after C; E after the C/D primitives it uses.** The control endpoint is needed at spawn, so install its native endpoint/environment capability before moving the spawn callers; the remainder of control dispatch can follow. **F** can develop alongside D/E, but its final authorization, quota, edit-report and hosted-session cutovers require B/C and the corresponding control/close consumers. **G** needs B, setup supervision, session-idle facts and H’s quit hooks.
- **H final:** only after desktop, paired, CLI/control, timer, OS event and recovery entry points all work natively. Replace the packaged-mode probe based on `app/out/main/index.js`, entry resolution and Node program lookup (`main.rs:1790–1804,1857`). Replace second-instance, quit, deep-link and failure handling; then remove host listener/token, `node::spawn`, watch and stop (`main.rs:1974–2019`). Delete `src/main/index.ts`, the obsolete Node host facade and main-bundle target. Retain `out/preload/tauri.js`, renderer assets, installed stock omp and necessary helper runtimes.
- **Packaging cut:** remove Node staging and `out/main` from `scripts/package-mac.ts:73,180–186` and `electron-builder.win.yml:18–36`; invert positive Node/main assertions in `scripts/after-pack.cjs:197–246` and `.github/workflows/release.yml:427–431,841–842`. Retire `package.json:10,22`, `scripts/build-node.ts`, the runtime pin and staging steps (`.github/actions/tauri-shell/action.yml:56`), and replace test Node overrides in `release.yml:465–488,873–891`. Update the scope checker’s Node entry rather than deleting coverage for retained page/stock code.
- **Proof on both packaged OSes:** inspect the signed macOS app and installed Windows artifact for absence of the Node executable **and** main bundle. Launch each under an isolated profile with no system Node on `PATH` or test Node override. Capture descendant **process starts from before launch through quit**, not a single idle snapshot. Exercise cold start, desktop invoke/send/push, a stock-backed tab, paired authorized and denied operations, tray/window close, second instance and ordinary quit. Assert no desktop Node launch and no orphaned app-owned children; distinguish stock Bun and OS WebView helpers from Node. Rehearse update from the supported predecessor, retained data/credentials, relaunch and failed-update rollback. Run the existing two-OS batch parity gate before landing; an empty `--remaining` alone proves none of this.

## 4. Open product decisions

**No inspected inventory reason establishes that the desktop Node process must remain.** The existing product choice explicitly retains Tauri’s system WebView, React and installed stock omp, not the desktop Node host (`.omp/rules/native-rust.md:11–24`). Three boundaries must not be treated as implicit permission to change the product:

- `src/main/models-config.ts` must preserve YAML comments/layout and stock normalization (`root.tsv:321`). A lossy serializer is not an acceptable port. A product decision is needed **only if proposing to drop that guarantee**.
- `src/main/model-release-dates.ts` must preserve existing trust roots, extra CAs, opt-in proxy handling and last-good cache (`root.tsv:310`). Switching silently to platform defaults is not equivalent. Changing network compatibility would need a decision.
- `resources/gui-bridge/stock-helper/{accounts,models,terminal-service,terminals}.ts` and `stats-host.ts` retain installed-stock APIs by design (`helpers.tsv:10–11,21–25`). Removing **all Bun/JavaScript processes** would be a different product goal. Their continued presence is not evidence that Node removal failed.
