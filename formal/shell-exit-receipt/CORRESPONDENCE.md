# Correspondence and limits

One Node client, one shell and at most one relaunch event and one exit request are modeled. The quit-emitted guard is set before listeners run, so reentrant or repeated `exit` is a stuttering step. A listener may enqueue relaunch before the exit call. Earlier multiple relaunches are abstracted to their final value, because the real lifecycle uses last-call-wins. Arguments are represented by presence only. Codes 0 and 7 stand for zero and nonzero. The code is selected with the request; acceptance records that same value. FIFO follows the synchronous client writes and the single Rust reader; frames are assumed intact until transport failure.

`boot` and `cef` identify the two paths to the same finalizer. `BeginStop` abstracts UI closure or BootExit delivery, and may happen before answer delivery. `JoinAndFinalize` combines successful child observation or kill-and-wait with relaunch attempt; it does not claim that spawning succeeds or that a new instance starts. Grace expiry is nondeterministic and may kill Node before the answer. No scheduling fairness, time bound, delivery guarantee or liveness is claimed. UnexpectedDeath abstracts both process and transport loss; before acceptance it is failure. After acceptance the real transport rejection also makes the shim exit, and the lifecycle ignores node-gone. Separate watcher/reader observations and their races are abstracted to one loss event.

The model excludes concurrent independent raw `app.exit` requests, CEF initialization failures and the boot/init race, startup timeout, OS kill failure, partial frames, shutdown-core internals, relaunch argument contents, and update installation. `NoPrematureEOF` concerns the shell's own accepted-stop stdin closure, not external crashes, timeouts or transport failures. The negative run is the old premature stdin-close behavior, not a claim about the current build. Nothing here establishes Windows installer acceptance.
