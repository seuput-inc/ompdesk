# Tauri system-WebView host

`ompdesk-tauri-shell` pins Tauri 2.12.5. WKWebView on macOS and WebView2 on Windows host the existing React page. The crate imports the existing shell's authenticated host wire, Node child supervisor and logger by path. `shell_core` is linked with default features disabled. This crate does not depend on CEF.

The runtime finds the actual Node main from `OMPDESK_APP_DIR` or the packaged `resources/app` layout. `OMPDESK_APP_ENTRY` can select an existing main bundle. Its sibling `renderer/index.html` and `preload/tauri.js` must exist. Missing assets are startup errors, not a fallback UI.

Node assigns window and webContents IDs. The registry never reuses them. Tauri labels bind native IPC callers to those IDs. App pages can load only the app custom origin. New-window requests and remote navigation are denied. The app document has no remote Tauri capabilities or child frames. Navigation advances a document generation, invalidates pending evaluations and rejects late invoke responses. Generation numbers travel in the preload's captured closure, not in React's API. Native-requested evaluation and pushes also check that generation before page-side execution. The ready transition and retained-push drain run in one UI-thread task.

`createOmpApi` uses the native `omp_ipc` command. Binary values retain the existing `$bin` representation. Node pushes queue until the preload is ready. Queue overflow produces the renderer's stream-reset signal. Native drag interception is disabled so HTML5 file drops reach the existing composer. `fs.pathForFile` returns an empty string for DOM `File` objects; picker, drop and clipboard attachments use the composer's existing text or upload-bytes fallback. No filename-to-path mapping is retained. Node-requested JavaScript runs through the native evaluator and its asynchronous result collector. This requires `unsafe-eval` in the app document CSP. The evaluator is not a CDP implementation.

The host implements app initialization, authenticated Node startup, app exit receipt, relaunch, ordinary app windows, native geometry/focus/visibility changes, app-page load, JavaScript evaluation, zoom and native Web Inspector. State updates precede their corresponding events. Exit keeps the host writer and Node stdin alive while Node receives its receipt, then joins the Node child and releases the single-instance listener before relaunch. Fatal Node loss exits instead of asking the disconnected backend to quit. Windows uses Tauri's local `http://app.localhost` custom-protocol origin. Saved outer-window sizes account for measured native frame insets.

## Incomplete runtime paths

This source is not a released application or a claim of parity. A real isolated-profile run with the actual Node bundle, handler invoke, push, second-window close and exit receipt is still required. A local cold Tauri build is intentionally not run by this worker. Main owns the hosted native compile and final artifact run.

The app WebView is not a CDP target. Preview uses the separate `shell-preview` Chromium driver. Native window, webContents and view IDs still come from Node and share one nonreused registry. Each Preview entry holds the actual Page and its CDP sessions; phone frames, capture, PDF, input, native painting and accessibility address that Page, not another browser target.

The native Preview surface adapts the same Page's PNG screencast, frame ACKs, OS input, UTF-16 composition, backend-node accessibility snapshots and DOM-range text geometry. This is a native raster surface, not an embedded Chromium view or a claim of WebContentsView parity. Actual macOS and Windows interaction, audio, clipboard/drag behavior and accessibility remain release gates until observed on the packaged app.
AX default actions verify the original focused backend immediately before trusted input, but a later asynchronous focus change can still occur between those two CDP commands because CDP exposes no backend-bound native DoDefault action.

Canonical session policy, cookies and streamed protocols remain in `sessions`. The private HTTP gateway reserves a partition listener before the actual BrowserContext is created. Mapping requires the canonical context's successfully applied explicit proxy bypass and live reservation. System proxy mode is preserved; it does not silently become DIRECT. Native Windows app-media requests redirect to a separate capability-bound loopback stream; only its exact allocated origin and the registered media origin are added to image/media CSP, never `connect-src`.

`automation::install` registers Main's native WebDriver only with the explicit Node test inspector, matching canonical test profile and requested unprivileged port. Ordinary launch opens no driver listener. `OMP_GUI_TEST_SHELL_FAIL_START=1` also requires that matching nondefault test profile; it fails after native initialization and before Node/page startup with phase `native-initialized-before-node`. macOS requires 14 or newer.

Profile import uses a private durable journal and an app-origin bootstrap before React reads localStorage. Missing destination keys are written and read back; existing destination values are retained. Source data and failed/partial imports remain available for retry. Automatic update/relaunch packaging, native interaction, original-profile upgrade/rollback and application-level parity still need Main's artifact gates. Unknown operations return `unsupported`, not simulated Chromium facts. The resource tree must be immutable while the app runs; canonical-path checking does not protect against a hostile local writer replacing files during an open.
