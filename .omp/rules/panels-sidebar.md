## Panels, sidebar and work views

### History, stats, compaction limits

- Composer history uses stock `HistoryStorage`. Reads (`history_recent`, `history_search`) go to the stock helper (`stock-helper/history.ts`, one handle on the shared history.db, unqueued beside the serial lane), never the tab's omp, whose thread a turn can starve. The write (`history_record`, needs the session id) stays a guarded bridge method. Local tabs share history with this machine's terminal omp; remote tabs use the paired host's history and never import client prefs. Legacy `inputHistory` prefs migrate oldest-first on the first successful local bridge load, then are deleted (`e2e/history-migration.e2e.ts`). Stock `shouldSkipHistory` keeps secrets out of SQLite. Transient recall and Up/Down draft restore stay renderer-local.
- Compaction-limit commit/prefill uses stock `config/compaction-threshold` helpers through `compaction_limits`; typing never waits for bridge validation.
- Stats: `resources/gui-bridge/stats-host.ts` runs the user's omp-stats server (stock `omp stats` always opens a browser) for live collection and stock DB reads. The Rust `stats` listener serves `/api/stats/requests`, pins the cursor to a snapshot and forwards dashboard reads to stock.
  - It starts stock's live ingest itself (`omp-stats/live` `statsLive().start()`: full sync at start and every 5 min, plus each transcript a session writes, 800 ms after), because stock starts it only when a dashboard page subscribes to `/api/events`, which the GUI never does; without it `~/.omp/stats.db` stops updating.
  - The host attaches its stdin shutdown before any startup await, so a start that never finishes cannot orphan it.
  - The frustration judge's module (`pi-coding-agent/judgment/standalone`) is imported inside the judge callback (called only on a `/api/frustration/*` request, which the GUI never makes), because loading it at start is most of the host's memory and start time.
  - **A hung host is replaced, and the figures stay** (Orca's dead scan worker, 25 Nov 2026; `crates/core/src/stats`). A read is bounded at 15 s (`front::fetch`). Past that the core asks the same server's `/api/status` (stock's in-memory ingest state, 2 s, `front::answers`): an answer means one slow query, a plain `stats_api_error`; none means the worker's loop is stuck, so the core kills it at once (`Host::hung`; its blocked loop would never read its stdin's end) and the restart ladder runs, and the read answers not-ready (`{ready: false, exhausted: false}`), which the reader takes as `stats.notReady`: `use-stats.ts` keeps the last figures, shows `stats.serverDown` over them past the boot budget and reads again until the new server answers; never a spinner. Pinned by the `answers` case of `stats/front.rs`.
  - Pinned by `stats-host-stock.test.ts` (installed omp: rows reach `/api/stats/requests` with no page open) and `stats-host.test.ts`.
  - **The last six weeks** (Orca FG67-69, 26 Nov 2026; `components/stats/DailyActivity.tsx`): Overview reads stock's local-day buckets (`/api/stats/overview?range=90d`, whatever range the page shows) into a 42-day grid (weeks as columns, five levels, the busiest day level 4; `dailyGrid`), three figures the buckets prove (active days, longest streak, busiest day) and a Share button whose dialog draws a 1200×630 card on a canvas in the window's theme (mark, the three figures, the grid, the repo address) to copy or save as a PNG. Orca's own counters (agents spawned, time agents worked, PRs created) have no record in stock's stats database and are not shown. Pinned by `DailyActivity.test.ts`.

- Terminal reuses stock `@oh-my-pi/pi-natives` `PtySession` inside the stock helper's terminals worker (`resources/gui-bridge/stock-helper/terminals.ts`, `src/main/terminal/`): no second native addon, one `TerminalService` per worker (overlapping first requests share its creation), stdin EOF kills every PTY. - **Startup input waits for the shell** (D90, Orca's shell-ready barrier): what a viewer types into a new or restarted PTY before the shell's first output is held in the worker (`Entry.queued`) and written, in order, with that first output or after `SHELL_READY_MS` (15 s) of silence; a shell that ended drops it. Pinned by "terminal startup input (D90)" in `terminal-service.test.ts`.
- **Terminals come back after a restart** (D92, Orca's PTY checkpoints; `src/main/terminal/history.ts`, the core's `crates/core/src/termhistory.rs`). The PTY never survives (the worker's stdin EOF kills it); what does is each terminal's output tail (`HISTORY`, 256 K UTF-16 units, cut at a line start and never inside a surrogate pair), the folder its shell is in at the save (`/proc/<pid>/cwd` on Linux, `lsof -d cwd` on macOS, the start folder on Windows), its shell and how it ended.
  - **The checkpoint is written where the scrollback is**: the core's stdout reader of the terminals worker (`stock/scrollback.rs`). Only a terminal of a window tab with a session file is kept (main sends `target.sessionFile` with each request, `""` for none; a paired device's tab and the agent's read send none and change nothing). Main asks the worker for the terminals that changed (`terminal.checkpoints {userData}`, held up to `HOLD_MS` 50 s until one changes, so an idle terminal costs nothing) every `CHECKPOINT_MS` (5 s) at most; the worker answers a frame with each one's unread output and `history.save` (folder, shell, end state), and the reader writes each file from its scrollback with `write_kept` (0600 file, 0700 folder; a full disk keeps it and writes it later). The quit's teardown (`terminals` step, before `sidecars`, bounded at `QUIT_SAVE_MS` 3 s; the core stops only after it) takes one last pass over every terminal and keeps them all: `disposeTerminals` ends nothing while quitting.
  - One file per terminal, `<userData>/terminal-history/<16 hex of SHA-256 of the session file>-<id>.json`. A terminal the person closes, or that goes with its closed tab, loses its file in the same reader (`history.drop` in the close or dispose frame, `remove_kept`, which also forgets content still waiting for space); that reader never writes it back for a checkpoint taken before the close. A tab moved to another session moves its files; a file nobody saved for 30 days is removed the next time a tab lists.
  - A tab's first terminal request after a launch lists its session's saved terminals (`terminalHistory.list`) and has the worker bring them back under their ids, oldest first (`terminal.restore`): the saved output, the dimmed `terminal.restored` line ("Restored after a restart: earlier output above, a new shell below" / "재시작 후 복원됨: 위는 이전 출력, 아래는 새 셸", after resetting the old program's screen modes), and a fresh shell in the saved folder (the tab's folder when it is gone; the saved shell when this computer still lists it). A terminal that had ended comes back ended with its exit or error and nothing started: a restored screen is never shown as a live process.

- **A viewer past the cut starts clean, and a blank screen asks for a redraw** (H139, H137): a `list` whose offset is older than the kept scrollback's head (the viewer fell more than 1 M units behind, a new viewport on a stream whose head was cut, another viewer's Clear) is answered by the core's scrollback (`stock/scrollback.rs`) with `gap: true` and output from the oldest kept unit, and the viewport resets xterm before writing it (`terminal-poll.ts` `reset`), so nothing shows with a hole in it. ### Split view and picking a session

- Files: `stores/tabs.ts`, rules in `shared/split-layout.ts`. Main owns tabs and the pool; the renderer owns what the window shows.
- A window shows one session alone or one split of 2–4 panes (`split`), and remembers the other splits it has shown (`rememberedSplits`: layouts only, no focus). A session is in at most one split, on screen or remembered.
- Three rules, all in `viewAfterPick`; every way of picking a session goes through `switchTab`: ① a pane of the split on screen only takes focus, the layout stays; ② a session outside the split leaves it and shows alone, full width, and the split on screen is remembered; it never replaces or opens into a pane; ③ a member of a remembered split brings that split back exactly as it was (sessions, positions, sizes) with the picked session focused, and the split that was on screen is remembered in turn.
- Picks: sidebar rows, ⌘1–⌘9, ⇧⌘[ ⇧⌘] / ⌘PageUp/PageDown when no split is on screen (with one they cycle its panes), tab overview, ⌃⇥ switcher, notification/prompt-card focus. The session picker (⇧⌘F) and the sidebar's stored-session rows open a session no tab holds as a new tab: a pick of an outside session (`switchSessionNow` never re-roots a pane's tab while a split shows; `activeTabUntouched` is false then).
- **A stored session of another folder opens as its own tab**, because stock's RPC `switch_session` refuses a session recorded in another folder (SESSION_CWD_CHANGE_REJECTED, answered `cancelled`). `switchSessionNow` and `requestSessionSwitch` (`opensInOwnTab` in `hooks/use-session-switch.ts`, the tab's cwd against the session's, compared as stock does) open it with `openTab` in its own folder and abort no running turn; only the tab's own folder switches in place. "Open in new window" (`SESSION_OPEN_NEW_WINDOW`) starts that window in the session's recorded folder (`sessionFolderState`, refused `session_folder_missing` when gone), its tab's omp on the session file (`spawnWindow` hands it to the pool as the tab's `--session`, not a boot `switch_session`; `SESSION_CONSUME_PENDING` answers null on the desktop, the web shim keeps its own). The fake omp refuses a cross-folder `switch_session` as stock does. Pinned by `use-session-switch.test.ts` and `e2e/session-picker-folder.e2e.ts`.
- The only edits of the layout: dropping a session on a pane edge (`splitTab`, drag-to-split, row menu's Split right/bottom) and the menu's Exit split view. A dropped session leaves the split it was remembered in; at four panes it replaces the pane under the pointer and that one leaves; Exit split view forgets the split. Closing a tab (`closeTab`, which a deleted session's tab goes through) and removing a pane drop the session from its split; a split left with one session dissolves.
- **A session row's drag does both**: the one native drag a stored row starts carries the split drag (`omp:tab-drag`, dispatched on `dragstart` only while a tab holds the session and it is not the pane in focus) and the reorder of its own list (see settings-layout-look › Sidebar projects). Dropped on a pane edge it splits (`SplitWorkspace`), on a row of its own list it moves, anywhere else nothing. The drop on a row also tells `SplitWorkspace` the drag is over (`omp:tab-drag` null), since a moved row may not get `dragend`. The pane in focus has no split drag but can still be moved within its list. Pinned by "a session open in a tab still drags onto a pane to split, and dropped on a row of its list it moves instead" in `Sidebar.test.tsx` and `e2e/sidebar-session-order.e2e.ts`.
- Sidebar: every row whose tab is a pane of the split on screen has `data-active`; the focused pane's row adds `data-pane-focus`. The focused row alone carries the wash and the accent ring; the other panes' rows (`data-pane-shown`) are outlined with a hairline and have no wash, so only one row reads as selected.
- Persistence: the renderer sends `rememberedSplits` with every `tabs.setView` (`tabs.setActive` only while neither side remembers any). Main keeps them per window (`#rememberedByWindow`, pruned on release, never overlapping what is on screen) and saves them as `splits` next to `split` in the tab layout (`PersistedTabLayout`, leaves are tab indices); `GET_TABS` returns each remembered split once, on its first tab (`rememberedSplit`).
- Tests: `shared/split-layout.test.ts`, `tabs.test.tsx`, `Sidebar.test.tsx`, `tab-layout.test.ts`, `sidecar-pool.test.ts`; e2e `split-select.e2e.ts` (3 panes: all selected, outside pick solo, member restores, relaunch), `split-drop`, `desktop-tabs`, `workbench-shortcuts`.

- **Several picked rows have one menu of their own** (`pickedMenuItems`): Archive N (only the rows no tab holds; disabled with its reason when every one is held) or Restore N, then Delete N…. **A phone swipe uncovers items of the row's own menu** (`sessionSwipeItems` picks Mark as unread and Archive or Restore by id, only when enabled), so neither list spells an item of its own.

A muted session shows no desktop banner and no phone push (main's `notifyMuted`, `SYSTEM_NOTIFY` answers `muted`, `WebPushNotifier` `muted`), and its terminal's bell sets no ✓; its ✓ and the waiting badge on the row stay.
- When a row reuses an untouched tab, `useSwitchingTabs` keeps that tab out of both reuse and automatic empty-tab cleanup from the first ownership lookup through hydration. A second pick can open beside it without waiting (`e2e/sidebar-session-order.e2e.ts`).
- **Diagnostics is one item**, "Save diagnostic bundle", present only while a tab holds the session (stock's `/dump` runs in that tab's omp, on the host for a host's tab): never a disabled pair. Holding Option/Alt while choosing it saves the anonymized bundle (`MenuSelectModifiers.altKey`), said on the item as its `hint` ("⌥ anonymized", "Alt anonymized" on Windows, "⌥ 익명화" in Korean; none on a touch screen). The anonymized item is also in Settings › Updates & about › Diagnostics (`DiagnosticsRow`: Save diagnostic bundle ▾ with both items); the palette has no diagnostics entry.
- **The host owns its rows.** Rename and Move to project use `sessions.rename` and `sessions.move` on the host. A moved session keeps its pin. Pin, Archive and Restore change the host's sidebar through `host.projects.command`, never the viewer's preferences. A host's session links are the host's (`sessions.links`, control-tools › Session links): its rows' tooltips read them from the host, "Link a PR or issue…" (and the Changes panel's link on a host's tab) adds and removes them there, and every change on the host comes back as `host.sessionLinks.changed` (26 Nov 2026: the row menu on a paired computer had no "Link a PR or issue…", the phone page did).

### Review notes, quotes and fix requests to the agent

- **One notes store** (`stores/review-notes.ts`; Orca's diff comments, MIT): a note on a Changes diff line or range (the + in `scm/DiffLines.tsx`, Shift+click or a drag for a range) or on a whole changed file, on a passage selected in the Files viewer (Markdown and code: `notes/FileSelection.tsx`, with the passage as its excerpt and the lines where the view numbers them), or a Preview pin (`PreviewFeedback.tsx`). - **One message** (`lib/review-notes.ts`): file notes in Orca's quote-safe block (`File:`, `Line:`/`Lines:`/`Scope: file`, an excerpt for a Files passage, the comment escaped inside quotes), then each Preview page under its header with its screenshots. ### Files the conversation names

- OMPdesk shows attached and handed-over files itself, on this computer and a paired one (the user's rule: no instruction to the agent; OMPdesk presents what the reply and the prompt name), never as raw paths.
- **One card** (`tools/media/FileCard.tsx`, its kinds and what each draws in one table, `KINDS`): a file with something to draw is a card (a picture, a PDF's first page, a page drawn in an empty-sandbox frame at four times the card's width and scaled down, a spreadsheet's or CSV's first rows, a presentation's first slide title), any other file a row (Word, archives, programs, text, folders) with a kind tile; under both the name, "type · rows/slides · size" (archives, text and other files by their extension, "ZIP · 1.0 KB") and the file's buttons. The tile stays under a preview until it is drawn, so a slow or failing read never leaves a blank box. A click on the card previews it (the Files viewer; a picture zooms); a right click opens its menu. Reads go through the tab's own `fs.*` (a paired host's tab reads on that host) once the card nears the screen. Audio and video stay `ChatMedia` players with the same buttons in their caption; a recording too large to play over the link is a chip with them too.
- **Its buttons** (`tools/media/file-actions.tsx`, one rule for the card, its ⋯ menu and a link's right-click menu in `lib/link-menu.tsx`): by `useFileSurface` (`local` this computer's tab, `remote` a paired host's tab in a desktop window, `web` the phone's page). The card's own button is the file's place: Reveal in Finder/Explorer here; Save to this computer from a host; Save to this device on the phone. The menu: Preview, Open in default app / reveal (here; on the phone they go to the computer through shim.ts's host actions), Save a copy…, Copy path. A save says where it went, with a reveal action that shows that copy whatever tab is in front (`fs.revealCopy` → `FS_REVEAL_COPY`, only for a path `FS_SAVE_COPY` wrote this launch), because `system.revealPath` asks the tab in front, usually the host's tab the file came from.
- **Saving** (`fs.saveCopy` → `FS_SAVE_COPY`, `src/main/save-copy.ts`): this window's save dialog, then a local `copyFile`, or from a paired host a 64 KB first read (`host.fs.readRange`, which says the size and that the host streams) so the dialog shows at once, then 8 MB parts (`HOST_DOWNLOAD_PART_BYTES`, up to `HOST_DOWNLOAD_MAX_BYTES` 1 GB) into a temp file of its own beside it (`<dest>.<random>.ompdesk-download`, opened `wx`, so a file or link already at a name like it is never truncated or removed), renamed onto the destination once whole and removed on any failure. A host without `host.fs.readRange` answers `unsupported`: one `host.fs.readBinary` (≤ 11 MB), else "update OMPdesk on that computer". A web window's call answers the file's bytes instead (`readWorkspaceBinary` here, `readRemoteFile` from a paired host in the same parts, both up to `FS_BINARY_LOCAL_MAX_BYTES` 100 MB; never the viewer's one-frame `host.fs.readBinary`, which stops at 11 MB), which ws-router puts behind a `/blob` URL past 512 KB like a read, and the shim hands them to the phone's browser to save or share (`env.save`).
- **Under a reply** (`chat/ReplyFiles.tsx` over `chat-media.ts` `referencedFiles`): media, pictures, PDFs, pages, documents and any non-text file the reply links or quotes (an archive, an installer: kind `file`), plus a text file it links by an absolute path outside the tab's folder (`/tmp/summary.md`). A file that is not there (moved, deleted, never written) draws nothing, on this computer and on a host's tab alike, never a "Deleted" card (`e2e/session-views.e2e.ts`, `e2e/remote-flows.e2e.ts`). A link with a line (`a.ts:42`) or inside the project is a citation and stays in the text; a picture a tool already showed is not drawn twice.
- **Under a prompt** (`PromptFiles`, `shared/file-mentions.ts` `splitAttachedMentions`, `replaceFileMentions`): every `@path` outside code that reads as a path (a separator or an extension: `@kim` is a person, `@pytest.fixture` in a fence and `` `npm i @types/node` `` are code) is a card under it; a line that holds only mentions (what the picker, drop and paste insert) leaves the text; a mention inside a sentence by its whole path (an upload, a file outside the project) reads as the file's name linking to it (a `file:` URL with `(`/`)` escaped, so a Windows drive, a space or a parenthesis survives sanitize), a relative one stays as written, and the punctuation around it stays; one a sentence names gets a card only while it names a file.

### Preview: agent browsing and agent visuals

- **Agent browsing** (Preview toolbar robot button, off until the user clicks it): the tab's bridge (`resources/gui-bridge/browser-relay.ts`) starts stock's own `omp browser-relay` server (`tools/browser/relay/server.ts`) on a free 127.0.0.1 port with a random extension token and holds `browser.relay`/`browser.relayUrl` as session runtime overrides, so stock's browser tool runs in relay mode.   - Electron's per-page debugger is not confined to its page (`Target.getTargets` lists the app window and `Target.attachToTarget` onto it works).   - `visual.open` in `crates/core/src/visuals` reads local sources (5 MiB) or inline HTML (2 MiB), matches records, writes version snapshots, prunes history and atomically saves the existing `history.json`. `visual.history` restores it; `visual.file` serves confined snapshot or asset bytes. Main keeps tab membership, the read mirror for synchronous window lookups, and response headers. `src/main/preview/visuals.test.ts` drives all three requests through `VisualStore`, including a core restart over existing snapshots.
  - Pruned filenames travel in the newly saved history (`retired` on its first record). An `ENOSPC` while recording v21 leaves v1 in place until the latest history lands. A successful retry, or reopening that history after a restart, removes only unreferenced snapshot files and empty visual folders. The generic `store.saved` notice is not proof that a retry wrote the file.
  - Sessions: each window's preview has two in-memory sessions reused by every preview host of that window, storage cleared when a host is disposed: `web` (`preview-<win>`) for every page the user, a popup, the agent's browser or a web visual browses, and `visual` (`preview-visual-<win>`) for file and inline visuals alone. Those load from `omp-visual://v<N>-<id>/…`, registered on the visual session only: the entry from its snapshot, other files from the entry file's own folder (the project folder when the entry sits at its root) by known asset type, never hidden paths or anything outside it. A page stays in the session it was made in (`PreviewPageState.session`): a visual opens in a visual-session page (an empty web tab is replaced, a web tab is never reused), an address typed on a visual's tab opens a new web tab, and the agent's browser never takes a visual's page.
  - Egress: every response (404 included) carries a CSP (`VISUAL_CSP`: `default-src 'none'` with each allowed kind named, `connect-src 'self' data: blob:`, `form-action 'none'`, no frames or objects) so the page cannot send what it reads off its origin by `fetch`, `sendBeacon`, `<a ping>`, WebSocket, image, CSS, prefetch, form or frame. What CSP does not cover the host refuses (Security #3): whatever a visual's page starts itself (link, `location`, form, meta refresh, frame load, redirect) goes only to another version of the same visual or `about:blank`/`about:srcdoc` (`visualMayNavigate`); popups never open; downloads are dropped silently; WebRTC runs with `disable_non_proxied_udp`; the visual session's proxy is a dead `http://127.0.0.1:1` with `<-loopback>`, so TURN over TCP and any other socket go nowhere.
  - DNS prefetch, which no CSP or proxy stops, is off app-wide: `index.ts` adds `dnsPrefetchingEnabled=false` to `--blink-settings` (merged with any given at launch) before ready; Blink applies it after each page's preferences in every frame and `x-dns-prefetch-control: on` cannot undo it.
  - A web address refused right after a real click or key on the page (the C143 gesture window) shows in full in a notice whose "Open in new tab" loads it in a web tab, only when the user picks it.
  - `e2e/preview-visual-egress.e2e.ts` pins all of it against a 127.0.0.1 sentinel (TCP and UDP) that must hear nothing and the visual session's net-log, which must hold no host resolution the page asked for.
  - The page keeps the Preview's sandbox (no preload, permission-less sessions). Comment on an element / region, pins, parent element and CSS variable tweaks run in an isolated world (`PAGE_WORLD`) on trusted events and go to the composer as one message; `choose` returns a `data-choice` click only when trusted: a real mouse/key release on that page within 1 s and neither the agent's relay nor any debugger holds the page. A region's screenshot takes a pen before it goes (`PreviewMarkup.tsx`, a dialog, so the native view hides under it): the strokes are drawn into the PNG the note keeps, in a fixed red that is no theme token because it is part of the picture.

### SSH tools on this computer

- `src/main/ssh/`, contract `src/shared/ssh-tools.ts`, Settings › SSH: port forwards for a saved host (`ssh -N -L 127.0.0.1:<local>:127.0.0.1:<remote>`, saved in `<userData>/ssh-forwards.json`, started again at launch), the server's listening ports every 5 s (`SSH_PORT_POLL_SECONDS`), ssh-agent/key state, and a reconnect with growing delay until the chosen grace time (1 min–7 days, default 1 h).
- Main (`service.ts`) keeps what the person wants running and the saved list; every such ssh runs in the core process (`client.ts`, `native/ompdesk/crates/core/src/ssh`, native-rust › 4b) and ends with it, with `-F <userData>/ssh/config`, whose first `Host *` block pins OMPdesk's own `known_hosts` with `StrictHostKeyChecking ask` and no connection sharing, then includes `~/.ssh/config`. OpenSSH hands `-F` to every ProxyJump hop, so each hop's key is checked too. What a host, a user, a key path and a port may be is the core's rule (`ssh/rules.rs`): nothing the page sends can become an ssh option.
- Host-key, password, passphrase and code questions come through `SSH_ASKPASS` (`ssh/askpass.rs`: the helper is the `ompdesk-core` binary itself, a per-process token over a local socket; the core lists the waiting questions for main in `ssh.prompts`) into `SshPromptDialog`; answers are never stored, never logged, cut out of that ssh's stderr before it is read, and a question expires after 2 min. A changed host key stops the forward until the user forgets the saved key.
- **A wake, an unlock or the connection coming back reconnects at once** (`SshTools.wake`, `wakeSshTools` in `ssh/ipc.ts`, called from `index.ts`' `powerMonitor` `resume`/`unlock-screen` and the connectivity monitor's `online`): a forward waiting on its delay connects now with a fresh budget (`attempt` 0, `droppedAt` cleared: the drop was the sleep's, not the server's). A ports watch whose ssh failed to start or ended by itself shows why and starts again on the forwards' delay ladder while its toggle stays on, and at once on a wake. Pinned by `ssh/service.test.ts` ("starts a ports watch again after its connection dropped").
- The agent's own ssh tool stays stock's. SSH server windows (a headless OMPdesk on the server) are out of scope: OMPdesk ships for macOS and Windows only, and remote devices cover running work on another of the user's computers.
